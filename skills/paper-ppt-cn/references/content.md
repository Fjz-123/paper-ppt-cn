# 跨学科论文内容组织

## 识别汇报类型

先根据任务确定是单篇精读、多篇比较还是专题综述，再识别研究类型。正文默认简洁学术表达，概念解释深度与听众相匹配。

| 研究类型 | 内容重点 |
|---|---|
| 算法、方法或工具 | 问题定义、输入输出、核心表示与模块、训练/推理、基线、消融和开销 |
| 实验或机制研究 | 科学问题、假设、实验设计、对照、关键结果与机制证据 |
| 临床或观察性研究 | 人群、设计、终点、效应与不确定性、偏倚和推广范围 |
| 材料或工程研究 | 设计与制备/实现、性能评测、对照条件、机制或工程权衡 |
| 数据集或资源研究 | 采集、构成、质量控制、覆盖范围、验证及使用边界 |
| 综述或理论研究 | 概念框架、分类与证据关系、假设或推导、分歧及开放问题 |

这些是组织提示，不是统一章节模板。机制论文不强行套“网络架构与消融”，综述不把每篇摘要依次排列。

## 多源资料取舍

阅读与补充检索优先覆盖以下重要信息：研究背景与实际/科学需求、既有方法的局限、研究动机、方法实现、网络/系统结构、创新点及对应验证。先定位论文引言、方法、主要结果和补充材料，不仅根据摘要或介绍页面写PPT。需要交代领域背景时，继续核查作者引用的关键原始工作或可信正式资料。

资料很多时，先围绕汇报目标建立问题或主题结构，选择能支撑主线的核心论文，其余作为比较与支撑。保留用户指定的必讲论文，说明其他资料未展开的原因。

对每篇核心论文回答：研究了什么、怎样实现或验证、相较既有工作的具体贡献、证据支持到哪里、哪些思想值得借鉴。跨论文比较围绕共同问题和可比条件，不能编造继承关系或强行排名。

笔记作为理解线索，结论仍回查原始证据；用户实验与论文报告分开标明，不把笔记推测写成作者结论。

## 方法、网络结构与创新

- 方法页应解释输入输出、关键表示或变量、模块交互、训练/实现过程和推理/使用流程，不能只列方法名称与性能。
- 核心论文涉及网络架构时，必须展示能够支撑解释的网络结构图。优先引用论文原图，必要时查看补充材料、作者项目页和官方代码资料，不用文字清单替代。
- 原图不可得但原文或官方实现足以确认拓扑时，可以忠实绘制结构示意图并标明“根据原文/官方实现整理”；不编造层数、连接、维度和模块功能。
- 找不到可靠结构依据时明确指出缺口并请求必要资料，不能声称结构图已完成。非网络研究展示适合其方法的实验设计或流程图，不虚构神经网络结构。
- 创新点应结合既有工作逐项说明变化、设计动机和证据，例如表示方式、目标函数、结构、监督、实验设计或理论发现。存在消融、对照或推导时要呈现对应证据。
- 关键结构图与实验图要有中文解释，图中的模块、箭头、图例和正文论述对应。

## 背景与方法衔接

需要背景时，用真实应用或科学意义说明问题，再引出研究瓶颈。背景长度取决于听众和总时长，不固定1–2页。

外部背景图片优先选正式机构、作者或项目页面，注明它展示的是应用、方法示意还是实验。不同技术路线或研究对象的案例不能冒充核心论文的实际部署或实验。

## 篇幅估计

- 明确页数和时长优先执行；所有总页数默认包含封面、目录和结束页，除非用户另有定义。
- 未指定时，依据核心论文数量、证据复杂度与汇报类型选择合适篇幅，说明估计值，不把30页/30分钟作为硬性默认。
- 图解、公式或关键实验分配更多讲述时间，目录、训练配置和次要比较相应精简；不假设每页讲述时间相同。
- 页数约束很紧时，优先保留论证链，辅助细节进入备注或备份页。严格总页数包括备份页，不能以隐藏页偷偷突破。

## 证据与表达

- 每页有清楚的解释对象或结论，图片必须支撑这一点。
- 结果按设置、指标、关键比较及有限结论展开。保留单位、样本量、对照条件、统计不确定性以及必要适用范围。
- 同一数字只放在对应实验条件下解释；不能把不同配置的精度、成本或不同人群的效果拼成虚假组合。
- 区分相关与因果、观察结果与机制推断、训练条件与测试输入、基础模型与专门调整后的能力。
- 创新点写成可定位的设计或发现，并提供对照、消融、推导或其他对应证据。
- 作者结论、用户实验和报告者启发分别表述。跨领域类比可帮助理解，但不能当作原文证据。
